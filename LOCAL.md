# Локальный запуск

Проект: `/Users/01.tech/Documents/autosim-new`.

```sh
cd /Users/01.tech/Documents/autosim-new
.venv/bin/python scripts/local-server.py
```

Сайт: https://localhost:4178

Админка: https://localhost:4178/adminka

Логин и сгенерированный локальный пароль: `.runtime/local-access.txt`.
При первом открытии подтвердите исключение для самоподписанного сертификата localhost.
Сервер слушает только 127.0.0.1. HTTPS нужен для защищённых cookies авторизации.

Конфигурация хранится в `.env`, отдельная SQLite-база — в `.runtime/autosim.sqlite3`.
Исходный скачанный архив сохранён в `.runtime/autosim-source-original.zip`.
Эти файлы исключены из Git. Не удаляйте базу при перезапуске.

SmartShell не подключён: архив не содержит действующих подключений,
аккаунтов и клиентской базы.

## Метрика и заявки

Перенесён счётчик `111096292` и цели `zayavka`, `messenger_click`, `phone_click`.
Метрика работает после согласия на аналитику. На localhost она отключена,
чтобы проверки не попадали в рабочую статистику. В админке и на странице
исходников Метрика не подключается. В кабинете Вебвизор отключён.
Настройки целей в самом кабинете Яндекса и привязка к Директу не менялись.

На главной в диалоге записи и по ссылке «Обратный звонок» внизу страницы
доступна форма без регистрации. `/api/leads` сохраняет заявку и очередь отправки
в SQLite. Повтор того же запроса не создаёт вторую заявку.

Telegram-код перенесён, но **живая отправка ещё не подключена**:
найденный токен старого `.env.local` некорректен, токен резервной копии отозван.
В `.env` перенесён ID чата из старого проекта; актуальность адресата нужно сверить
с конфигурацией работающего сервера. `TELEGRAM_UPDATE_MODE=disabled`, worker не запущен.
Для подключения нужен действующий `TELEGRAM_BOT_TOKEN` из конфигурации рабочего сервера.
Не меняйте токен в BotFather ради поиска: это отключит работающего бота.

После получения действующих настроек запускайте worker:

```sh
.venv/bin/python scripts/local-worker.py
```

Режимы `TELEGRAM_UPDATE_MODE`:

- `disabled`: Telegram отключён, заявки остаются в очереди.
- `webhook`: сервер принимает `/api/telegram/webhook`, worker обрабатывает
  сохранённые обновления. Нужен `TELEGRAM_WEBHOOK_SECRET` длиной от 32 символов;
  такой же secret_token задаётся при регистрации webhook.
- `polling`: worker получает обновления напрямую. Допустим после остановки
  предыдущего получателя; при активном webhook запуск останавливается.
- `outbound`: только отправка уведомлений, без получения действий Telegram.
  Этот режим не обеспечивает работу кнопок и комментариев.

Не запускайте два получателя обновлений одного бота. Переключение рабочего webhook
или polling выполняется при согласованном переносе сервера. Для локальной проверки
всего процесса используйте отдельного тестового бота либо согласованный канал доставки.
При проблемах с сертификатами Python задайте `SSL_CERT_FILE` с доверенным CA bundle;
не отключайте проверку TLS. При необходимости доступен `TELEGRAM_PROXY_URL`.

Перенесены «Взять в работу», «Вернуть в новые», завершение с комментарием/без него,
автозавершение после часа ожидания комментария, напоминания новым заявкам через
5/10/15 минут и взятым в работу через 1/3/5 часов. Команды: `/new`, `/active`,
`/done`, `/retry_failed`, `/ping`, `/chat_id`. Уведомления из кабинета используют
существующую очередь бронирований и `BOOKING_OWNER_ID` / `TELEGRAM_OWNER_IDS`.
Старая история заявок MongoDB не импортирована: доступа к рабочей базе пока нет.
У новых карточек собственные идентификаторы; старые сообщения обслуживает прежний бот.

Временная ошибка Telegram вызывает повтор отправки из очереди. Если Telegram принял
сообщение, но соединение оборвалось до ответа, при повторе возможен дубль сообщения;
сама заявка в базе при этом остаётся одной.

Зависимости устанавливаются в `.venv` из `server/requirements.txt`.
Команда `npm run dev` из исходного архива запускает только статические файлы;
для сайта с рабочим API используйте команду выше.
