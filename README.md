# АВТОСИМ

Сайт, кабинет пилота, бронирование, мини-игра, админка и SmartShell. HTML/CSS/JS без сборщика; Python API. В архиве нет базы, аккаунтов, паролей и действующих подключений.

## Установка на сервер
1. Linux-сервер с Docker Compose и Python 3.12+. Домен направьте на сервер, откройте порты 80/443.
2. Распакуйте архив и перейдите в папку `autosim`.
3. Выполните `python3 scripts/setup.py`. Укажите домен, логин владельца (по умолчанию `admin333`) и **новый пароль**. Команда создаёт приватный `.env`; владелец определяется его хешем, а не готовой записью в архиве.
4. `mkdir -p releases && docker compose up -d --build`.
5. Откройте `https://ВАШ-ДОМЕН/adminka`, войдите созданным владельцем. Сотрудники и роли создаются в «Команда и роли».

HTTPS выдаёт Caddy автоматически. База SQLite хранится в Docker-томе `data`; её нет в каталоге сайта. Не открывайте порт приложения 8000 наружу. Текущий облачный ресурс использует YDB; бизнес-логика общая.

## Подключение клуба
- В `.env` заполните `SMARTSHELL_WRITE_CLUB_ID` своим ID клуба, затем `docker compose up -d --force-recreate`.
- В админке → SmartShell войдите аккаунтом клуба, проверьте тариф/доступные модули, сопоставьте 7 Standard, 2 Pro, 1 VIP и включите синхронизацию. Токен только с `payment_create` не даёт общего доступа. При несовпадении ID запись заблокирована. Внутреннее значение режима `test` сохранено для совместимости и обозначает разрешённую запись именно в указанный клуб.
- Старых клиентов свяжите вручную через карточку клиента. Новый профиль может требовать подтверждения телефона SmartShell. Часовой пояс клуба — Оренбург, UTC+5.
- Telegram: создайте бота через BotFather; в `.env` задайте `TELEGRAM_BOT_TOKEN`, `BOOKING_OWNER_ID` (числовой ID первого владельца), `TELEGRAM_OWNER_IDS` (1–2 ID через запятую). Владельцы отправляют боту `/start`. Перезапустите контейнеры. Используйте отдельного бота без активного webhook: worker получает обновления через long polling. Доставка, подтверждение, перенос и отмена входят в worker.

## Исходники и обслуживание
- `/` — сайт, `/cabinet` — кабинет, `/adminka` — управление, `/source` — скачивание исходников. `/apple` перенаправляет на `/`.
- `python3 scripts/package-release.py` создаёт `output/autosim-source.zip`. Для своей страницы скачивания скопируйте его в `releases/autosim-source.zip`; пароль задаётся при setup и хранится только хешем. Никакого универсального пароля в архиве нет.
- Перед обновлением: `docker compose stop app worker`, затем `docker compose run --rm --no-deps app python -c "import sqlite3; sqlite3.connect('/data/autosim.sqlite3').backup(sqlite3.connect('/data/backup.sqlite3'))"`, затем `docker compose up -d --build`. Копию держите приватно, периодически переносите в защищённое хранилище.
- Не удаляйте Docker-том `data` при обновлении. Не меняйте `SESSION_SECRET` без плана миграции: он шифрует токены интеграции. Для чистой установки используйте новый том и заново подключите клуб.
- `docker compose logs --tail=100 app worker` — диагностика без паролей и содержимого запросов.

## Доработка человеком или ИИ-агентом
Прочитайте `AGENTS.md`. Дизайн задаёт `.agents/skills/autosim-glass/SKILL.md`; используйте его для сайта, кабинета и админки. Для Codex папку `autosim-glass` можно скопировать в `~/.codex/skills/` и вызывать `$autosim-glass` (или передать агенту путь к SKILL.md).

Меняйте существующие компоненты `public/`, серверную логику — в `server/`. Не переносите реальные данные в тесты. Проверки: `pip install -r server/requirements.txt`, `python3 scripts/test-all.py`, `node scripts/check.mjs --current` (Node 22+). Для JS-тестов сначала `npm install` (зависимости только для разработки). Дополнительные JS-регрессии находятся в `scripts/test-*.mjs`. Визуальные изменения проверьте на мобильном и настольном экране. Отчёт и ограничения — `docs/release-checks.md`.

После правок пересоберите контейнеры и архив. Публикация, сброс базы и операции в работающем SmartShell требуют соответствующего задания владельца. Дизайн Glass — браузерная реализация, а не нативный материал iOS.


## Перенесённые интеграции

На сайт добавлены прежний счётчик Метрики 111096292 и цели, форма обратного звонка
без регистрации и полный Telegram-процесс обработки таких заявок. Подробности,
локальный запуск и состояние подключения описаны в `LOCAL.md`.

Для этого процесса дополнительно задайте `TELEGRAM_ADMIN_CHAT_ID`. В режиме
`TELEGRAM_UPDATE_MODE=webhook` запросы приходят на `/api/telegram/webhook`,
проверяются по `TELEGRAM_WEBHOOK_SECRET` и обрабатываются worker из очереди.
В режиме `polling` активного webhook быть не должно. Одновременно должен работать
только один получатель обновлений бота. Нельзя переключать работающего бота,
пока не подготовлен перенос его конфигурации и необходимых данных.


## Подготовка переноса с работающего Next.js-сайта

В новой папке на том же сервере выполните `python3 scripts/prepare-migration.py`.
Скрипт найдёт работающий контейнер Compose-сервиса `autosim`, прочитает его
настройки Telegram без вывода секретов и попросит задать логин/пароль новой
админки. Создаст `.env` с правами 0600; существующий файл не перезаписывается.
Старые контейнеры и база не меняются. После этого:

```sh
docker compose -p autosim-new build app worker
```

Это только сборка образов. Новый получатель Telegram отключён до переноса
истории заявок и переключения обработки обновлений. Перед запуском необходимо
решить маршрутизацию портов 80/443 и доступ к существующему прокси Telegram.
Если найдено несколько старых контейнеров, укажите `--container ИМЯ`.
