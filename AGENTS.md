# Работа с АВТОСИМ

## Перед изменением
Прочитайте README. Для UI используйте `.agents/skills/autosim-glass/SKILL.md`. Уточняйте только отсутствующие решения, влияющие на результат; обычные обратимые правки выполняйте в рамках запроса пользователя.

## Карта проекта
- `public/`: HTML, CSS, ES-модули и локальные ресурсы. Сборщик не требуется.
- `server/app.py`: API, auth/CSRF/валидация; остальные модули разделены по предметной области.
- `server/storage.py`: YDB. `server/sqlite_store.py`: транзакционная БД отдельного сервера. `server/wsgi.py`: HTTP-адаптер Docker.
- `server/smartshell*.py`, `seat_booking.py`: интеграция и занятость; только фиксированные операции GraphQL с переменными.
- `scripts/worker.py`: фоновые задания и Telegram на отдельном сервере.
- `.agents/skills/autosim-glass/`: правила дизайна. `/apple` перенаправляет на главную.

## Инварианты
Не считайте секретный адрес защитой. Права проверяются сервером на каждой операции. Не интерполируйте пользовательские значения в SQL/YQL, HTML, shell или GraphQL. Для текста используйте `textContent`. Сохраняйте строгие схемы JSON, CSRF, Origin, ограничения тела/частоты и изоляцию профилей.

Время клуба — UTC+5; сеансы начинаются в целый час. Всего 7 Standard, 2 Pro, 1 VIP. Цена и доступность определяются сервером. Подтверждение использует существующий резерв; не создаёт дубль. Перенос и отмена синхронизируются с тем же объектом SmartShell. При недоступности внешнего расписания не показывайте выдуманные свободные места.

Награда доступна текущему лидеру. Возвращение на первое место после другого лидера или новая неделя даёт новый час; улучшение собственного результата без потери лидерства — нет.

Не включайте `.env`, БД, дампы, токены, текущих владельцев, подключения, логи посетителей и `.runtime` в архив. `scripts/package-release.py` использует список разрешённых файлов. Сброс БД и изменения работающего SmartShell выполняйте только при явном запросе пользователя; сначала обеспечьте возможность восстановления.

## Проверки и публикация
`python scripts/test-all.py`, `node scripts/check.mjs --current`. Запускайте затронутые JS-тесты; визуальные изменения проверяйте в браузере. Для новых API проверяйте не только успех, но и отсутствие сессии, чужой профиль, неверную роль, CSRF/Origin, повтор запроса и некорректные типы.

Не заявляйте абсолютную безопасность. В отчёте разделяйте выполненные тесты, ручной аудит и ограничения. Не повторяйте тесты без причины после успешного прохождения. Публикуйте только в согласованную среду, с возможностью возврата предыдущей версии. Продакшн-учётные данные агенту в чат не нужны.
